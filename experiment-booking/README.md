# 2026 아인슈타인 동아리 방과후 실험 신청

학생용과 교사용이 **하나의 Google Apps Script 웹 앱 URL**에서 열립니다.
기본 화면은 학생용이며, 상단 **교사용** 버튼을 누르면 교사용 PIN 로그인 화면이 표시됩니다.
비밀번호 입력란 아래의 문구는 요청하신 안내 문구이고, **진짜 인증은 서버에서만 검증**합니다.

- 2026-11-04(수) 방과후 — 11-03 23:59까지

- 2026-11-06(금) 방과후 — 11-05 23:59까지

실험 당일 00:00부터 서버가 신규 신청을 차단합니다.

## 제공 기능

- 학생: 대표학생 학번/이름 → 날짜 → 참석자 명단(행 추가) → 실험 주제·목적·방법 → 구입 준비물(품목명/종류·규격/수량/단가/G마켓 링크, 행 추가) → 과학실 보유 준비물(행 추가) → 최종 제출
- 교사: PIN 로그인, 날짜별 신청 접수 관리, 신청서 조회, 승인·보완 요청, 구매 상태, CSV 내보내기
- 학생은 학번·이름으로 접속하지만 별도의 신원 인증은 하지 않으므로 **타인 신청서 조회·수정 기능은 제공하지 않습니다.**

## 설치 방법 (Google Apps Script, 교사용 Google 계정)

1. [Google Apps Script](https://script.google.com/)에서 새 프로젝트를 생성합니다. 기존 프로젝트를 수정하는 경우에는 **원본 코드와 스프레드시트를 먼저 백업**합니다.
2. `Code.gs`를 프로젝트의 `Code.gs`에 붙여 넣고, HTML 파일을 `Index`라는 이름으로 만든 다음 `Index.html` 내용으로 교체합니다.
3. Apps Script **프로젝트 설정 → 스크립트 속성**에서 아래 항목을 추가합니다.
   - 속성 이름: `LAB_ADMIN_INITIAL_PIN`
   - 속성 값: **교사가 정한 4자리 숫자 PIN** (GitHub 코드/README에 값 공개 금지)
4. **신규 설치라면** 함수 `setupApp_`을 Apps Script 편집기에서 직접 실행합니다. 그러면 관리용 Google 스프레드시트가 생성되고, PIN은 솔트를 이용해 해시로 저장되며 최초 입력 속성은 삭제됩니다.
5. **기존 설치로 `LAB_DB_ID`가 이미 등록되어 있다면** `setupApp_`을 재실행하지 말고 `configureAdminPin_`을 편집기에서 실행합니다. 이때 기존 신청 데이터를 보존하고 교사용 PIN만 갱신합니다.
6. 프로젝트 시간대를 `Asia/Seoul`로 지정합니다. 웹 앱을 **실행 사용자: 나(교사)**, 학생들이 접근할 수 있는 적절한 액세스 권한으로 배포합니다.
7. 배포 후 발급된 **동일한 `/exec` 주소 하나만** 학생·교사에게 공유합니다. 교사용은 화면 상단 **교사용** 버튼을 클릭합니다.
8. 업데이트하는 경우 **배포 관리 → 수정 → 새 버전**을 선택하여 실제 웹 앱에도 최신 코드를 적용해야 합니다.

## 보안 설계와 주의사항

- 교사용 PIN/해시/솔트는 브라우저 HTML이나 공개 GitHub에 포함되지 않고 **Apps Script 비공개 스크립트 속성**에 보관됩니다.
- 교사용 데이터 조회 및 변경 API는 모두 서버 측 인증 검사를 통과해야 실행됩니다. URL이나 HTML 버튼을 조작하는 것만으로는 조회할 수 없습니다.
- PIN 성공 시 예측 불가능한 임시 세션 토큰을 발급합니다. 토큰은 **30분 뒤 만료**되고 브라우저 메모리에만 있으며, 로그아웃하면 서버 캐시에서 제거합니다.
- 인증 실패가 **5회 누적되면 20분간 로그인 시도를 차단**합니다. 제한은 전체 앱에 공통 적용되어 누군가 반복 시도하면 교사 로그인도 일시적으로 막힐 수 있습니다.
- **숫자 4자리 PIN은 강력한 인증 수단이 아닙니다.** 이것으로 해킹을 완전히 방지한다고 보장할 수 없으며, 필요하면 더 긴 비밀번호나 학교 Google 계정 기반 인증으로 전환해야 합니다.
- 저장된 스프레드시트는 학생 개인정보를 포함하므로 학생에게 직접 공유하지 마세요.
- GitHub Pages에서 HTML만 열면 `google.script.run` 서버가 없어 실제 신청 저장은 작동하지 않습니다.

## 배포 전 점검

- 학생 신규 제출, 전날 마감 차단, 중복 대표학번 차단
- 잘못된 교사 PIN → 실패, 올바른 PIN → 교사용 신청서 조회
- 브라우저 새로고침 → 교사 로그인 다시 필요
- 학생용 복귀/교사 로그아웃 → 이전 교사 세션 접근 차단
- 교사 승인·구매 상태 변경 및 CSV 내보내기
